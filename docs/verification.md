## Зависимости от поведения штатного движка

У этой версии пустая задача не всегда материализована после `thread/start`.
Перед сменой провайдера необходим `thread/read(includeTurns=true)`, затем
unsubscribe/resume. Legacy read может вернуть точно `-32601: list_turns is not
supported yet`, материализовав запись. Только эта ошибка допускается.
Повторение возможно лишь для кратковременного отсутствия metadata rollout;
пользовательский `turn/start` автоматически не повторяется.

У Claude штатный Codex хранит только метаданные задачи. Нативный список исключает
такие записи без своих ходов. Адаптер дополняет страницы своими метаданными и
историей Claude; таблицы штатной базы не редактируются. Маршрут и session ID
сохраняются до отправки сообщения. Незавершённые ходы при восстановлении
помечаются прерванными и не отправляются снова.

При resume явно передаются сохранённые cwd и настройки разрешений. Для фильтра
cwd учитываются списки путей и эквивалентность macOS `/var` и `/private/var`.

## Обнаружено при запуске основного окна

Одно приложение создало два экземпляра адаптера, использующих общий реестр.
Поэтому PID в last-session.json и desktop-menu.json может различаться;
при проверке учитывается родительский процесс приложения. Перед дальнейшей
приёмкой Claude нужно проверить владение активными сессиями и восстановление
при появлении второго служебного процесса: текущие блокировки находятся
в памяти каждого процесса, а Registry.recover выполняется при каждом старте.
Действующих задач Claude на момент этого наблюдения в реестре не было.
Это было исходное наблюдение; исправление и его пределы описаны ниже.
