# Субагенты с выбором модели

Реализовано 20.09.2026. Модель выбирается отдельно для каждого дочернего
исполнителя. Общей настройки «всегда DeepSeek» нет.

## Как включить в приложении

1. После завершения текущей работы полностью закрыть Codex через **⌘Q**.
2. Открыть существующий `bin/Codex Bridge.app`.
3. Создать **новую задачу**, выбрать основную модель и дать поручение.

Пересобирать `.app`, устанавливать пакеты или вводить ключи заново не нужно.
Запускатель использует обновлённые исходники адаптера. Основное приложение
во время разработки не перезапускалось.

Инструменты делегирования добавляются при создании задачи. У новых задач
они сохраняются и после перезапуска — это проверено на штатном Codex.
Старые задачи OpenAI/DeepSeek, созданные до обновления, автоматически их
не получают: установленный `thread/resume` не принимает `dynamicTools`.

## Примеры поручений

> Основную работу выполняй сам на Astra. Через bridge_agents запусти субагента
> на deepseek-flash для анализа этих файлов. Дождись результата и проверь выводы.

> Запусти через bridge_agents двух субагентов: claude-code/sonnet для ревью,
> gpt-6-astra для проверки архитектуры. Основную модель не меняй.

> Запусти субагента через bridge_agents без указания модели. Пусть проверит
> предложенное решение и вернёт замечания.

В последнем примере родитель Astra создаст Astra, DeepSeek — DeepSeek,
Claude Sonnet — Claude Sonnet. Наследуется актуальная модель задачи, а не
последний глобальный выбор в меню. Effort также наследуется, если допустим
для выбранной модели; иначе используется её стандартное значение. Явно
указанный неподдерживаемый effort возвращает ошибку.

Для постоянной инструкции проекта можно добавить в его `AGENTS.md`:

```text
Когда требуется делегирование с выбором модели, используй bridge_agents.
Если модель субагента явно указана в поручении, передавай её в model.
Если модель не указана, не задавай model: субагент наследует модель родителя.
Не заменяй недоступную модель другой без сообщения пользователю.
Перед финальным ответом дождись результатов запущенных субагентов.
```

Это пример инструкции; пользовательские проекты автоматически не менялись.

## Доступные операции

| Инструмент в `bridge_agents` | Назначение |
|---|---|
| `spawn_agent(message, model?, reasoning_effort?, task_name?)` | Запустить дочернюю задачу, вернуть её ID и фактическую модель |
| `wait_agents(targets, timeout_ms?)` | Получить состояние и ответ; ожидание до 60 секунд, повторное ожидание не запускает работу заново |
| `send_message(target, message)` | Продолжить завершившегося исполнителя в его сессии на той же модели |
| `interrupt_agent(target)` | Остановить выбранного исполнителя с его потомками |
| `list_agents()` | Показать дочерние задачи текущего родителя |
| `list_models()` | Получить точные идентификаторы моделей из текущего каталога |

OpenAI: `gpt-6-astra` и другие доступные модели штатного каталога.
DeepSeek: `deepseek-flash`, `deepseek-v4-pro`.
Claude: `claude-code/default`, `claude-code/opus[1m]`,
`claude-code/claude-fable-5-1[1m]`, `claude-code/sonnet`, `claude-code/haiku`.
Наличие модели в списке не доказывает доступность каждого варианта в аккаунте.
Неизвестные идентификаторы отклоняются без подстановки другого провайдера.

OpenAI выполняется встроенным Codex с текущим входом ChatGPT. DeepSeek — через
свой API и существующий ключ. Claude — официальным CLI с текущим входом Claude.
Вызов Claude inference никогда не отправляется штатному OpenAI endpoint.

## Поведение и ограничения

- Это инструменты адаптера с настоящими дочерними сессиями. Механизм выбора
  модели встроенного `multi_agent_v1` и пакет приложения не изменялись.
  Результат возвращается в родительскую задачу как ответ инструмента.
- Проверены реальные вызовы Astra → Astra/DeepSeek/Claude и Claude → DeepSeek.
  Отображение новых дочерних задач и запросов подтверждения в основном окне
  ещё требует пользовательской проверки. Наличие штатных карточек субагентов
  или точно такого же дерева в интерфейсе не обещается.
- Субагент получает сформулированное родителем поручение и рабочую папку.
  Полная переписка родителя автоматически не копируется между провайдерами.
  Нужный контекст следует включить в `message`.
- Передаются текущие разрешения и политика песочницы. У отдельного Claude CLI
  остаются ограничения, описанные в README: для Bash/Write/Edit нужны ручные
  разрешения, read-only запрещает эти операции, песочница Codex не становится
  системной песочницей процесса Claude. Вызов инструмента делегирования сам
  по себе не разрешает дочерние команды или изменения файлов.
- До четырёх активных дочерних задач на одного исходного родителя, глубина до
  трёх уровней. Все работают в одной рабочей папке; отдельные worktree не создаются.
- Управляемого ребёнка продолжают из родителя через `send_message`; отдельная
  отправка хода в его задаче отклоняется, чтобы два окна не запустили его одновременно.
- `send_message` принимает новое поручение после завершения/остановки ребёнка.
  Вмешательство сообщением в ещё выполняющийся ход пока не поддерживается.
- Остановка родительского хода останавливает его дочернюю работу; остановка
  одного ребёнка не затрагивает родителя и соседей. Уход с задачи сам по себе
  не останавливает исполнителей.
- Общий SQLite и блокировки ОС предотвращают повторную отправку одного
  tool call и одновременный запуск одной Claude-сессии двумя адаптерами.
  Второй адаптер может читать результат и ожидать завершения. Управление
  активной задачей другого адаптера возвращает явную ошибку; перенаправление
  команд владельцу через IPC пока не реализовано.
- После потери подтверждения отправки статус `uncertain`: автоматического
  повтора нет. Завершённые результаты сохраняются; обычное продолжение
  завершённого ребёнка использует прежнюю сессию.
- Субагенты получают каталог включённых навыков Codex и `bridge_skills`.
  Переданные приложением dynamic tools и выбранные корни возможностей
  наследуются и сохраняются после перезапуска. Подробности, ImageGen и
  ограничения зависимостей: [skills.md](skills.md).
- Claude получает встроенные MCP `bridge_agents` и `bridge_skills` через официальный SDK
  control protocol. `--safe-mode` и `--strict-mcp-config` сохраняются; сторонние
  MCP, hooks и плагины не подключаются. Новых сетевых портов нет.

Отключение новых инструментов: `enable_agents = false` в секции `[bridge]`
локального `bridge.local.toml`, затем перезапуск. Старые сохранённые вызовы
делегирования в таком режиме возвращают явную ошибку. Обычные задачи остаются.
Общий возврат к штатному приложению описан в README.

Доказательства: `test-results.txt`, `native-agents.json`,
`live-agents-astra.json`, `live-agents-claude.json`.

Источники протоколов: [Codex App Server](https://learn.chatgpt.com/docs/app-server),
[субагенты Codex](https://learn.chatgpt.com/docs/agent-configuration/subagents),
[официальный SDK control protocol Claude](https://github.com/anthropics/claude-agent-sdk-python/blob/main/src/claude_agent_sdk/_internal/query.py).
Решение проверено на установленной версии: её штатный `spawn_agent` принимает
модель, но не отдельный провайдер; поэтому добавлен собственный координатор.
